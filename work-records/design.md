# 作業記録HTML デザインガイド
作成日: 2026-08-13

## 目的

作業記録HTMLを、あとから自分が作業内容、判断、結果、残件を確認するための内部記録として統一する。広告、紹介ページ、成果の演出には使わない。

## 情報の書き方

- 事実、件数、実行日、結果を先に書く。
- 見出しは「実行結果：更新0件」「未完了Issue：12件」のように、内容をそのまま記載する。
- キャッチコピー、比喩、余韻を持たせた表現、成果を大きく見せる表現は使わない。
- 同じ事実をタイトル、説明文、大きな数値で重複させない。
- 説明は、判断理由や再実行に必要な情報が増える場合だけ加える。
- 「安全に守る」「最も安全な結果」のような評価語は、具体的な条件や検証結果へ置き換える。

## 言語

- 画面に表示する文章は、原則としてすべて日本語で記載する。
- 英語のキャッチコピー、英語だけの見出し、英語の状態表示は使わない。
- GitHub、SQL、CSV、live DB、`player_id`、ファイル名、コマンド名など、固有名詞・識別子・技術上そのまま示す必要がある語だけは英語表記を許容する。
- `open`、`closed`、`parent`、`child`、`related`、`verified`、`updates` などは、本文表示では「未完了」「完了」「親Issue」「子Issue」「関連Issue」「検証済み」「更新件数」のように日本語化する。
- 日付、件数、判断理由は曖昧なコピーに置き換えず、具体的に記載する。

## 基本トーン

暖色の紙面に黒い文字を置く、簡素な内部文書を基本とする。情報の階層は余白と罫線で示し、広告的なヒーロー表示や抽象的な装飾は置かない。

## 色

| 名称 | 値 | 用途 |
|---|---|---|
| エッグシェル | `#fdfcfc` | ページ全体の背景 |
| ウォームトープ | `#f5f3f1` | 重要な結果や入力情報を示す面 |
| ストーン | `#ebe8e4` | 1pxの区切り線 |
| インク | `#000000` | 見出し、本文の主要文字 |
| グラファイト | `#44403b` | 補助見出し、強い補足 |
| スモーク | `#777169` | 説明文、注釈 |
| アッシュ | `#a59f97` | 行番号など最も弱い情報 |

- 純白の大きなカードや強い影は使わない。
- 色は情報の区切りと可読性のためだけに使う。抽象的なグラデーションや挿絵は原則として使わない。

## タイポグラフィ

外部フォントを必須にせず、Interまたはシステムフォントで成立させる。

| 役割 | 推奨サイズ | ウェイト | 行間 |
|---|---:|---:|---:|
| ページタイトル | `32–44px` | `400` | `1.15–1.25` |
| 大見出し | `24–32px` | `400–500` | `1.25–1.4` |
| セクション番号・名称 | `18–20px` | `500` | `1.4` |
| 小見出し | `18–20px` | `500` | `1.45` |
| 本文 | `16px` | `400` | `1.5–1.7` |
| 補足 | `14px` | `400` | `1.5–1.6` |
| 技術文字列 | `13px` | `400` | `1.6` |

### セクション見出し

- `01 / SCOPE` のような小さな英語ラベルは使わない。
- `01　対象`、`02　判断事項`、`03　成果物` のように、番号と日本語名称を18px以上で表示する。
- 番号と名称は本文から明確に識別できる大きさ・濃さにする。
- その直後に24〜32pxの日本語見出しを置き、対象、件数、結果を端的に示す。
- セクション番号・名称と大見出しで同じ意味を繰り返さない。

## レイアウト

- 最大幅は`1280px`、PCの左右余白は原則`64px`とする。
- セクション間は`64–88px`を目安とする。
- 情報のまとまりはカードの数ではなく、余白と`1px solid #ebe8e4`の区切り線で示す。
- 強調面は結果確認に必要な場合だけ使い、`#f5f3f1`、影なしで表現する。
- 大きな数字、広い空白、角丸面を視線誘導だけの目的で使わない。
- 320px幅でもページ全体の横スクロールを発生させない。
- ファイル名や技術識別子には`overflow-wrap: anywhere`を指定する。

## チップ・ボタン・状態表示

- 件数、状態、分類、親子関係をチップやバッジで囲まない。
- 複数のチップを横並びにして情報を表現しない。
- 「検証済み・対象117選手・実更新0件」のように、普通の文章、定義リスト、罫線区切りのメタデータとして表示する。
- ナビゲーションリンクも原則として通常のテキストリンクにする。
- 黒い塗りボタンやピル形状は、明確な操作が必要な場合に限る。作業記録HTMLでは通常不要とする。

## GitHub Issueの表示

### 共通フォーマット

- GitHub Issue状況は作業記録HTMLの末尾に、`## GitHub Issue状況（YYYY-MM-DD時点の現在値）` という見出しで置く。
- セクションの冒頭に `確認日: YYYY-MM-DD（JST）` と、GitHub APIで対象プロジェクトの最新情報を取得したことを記載する。
- `work_record_010.html` と同じく、「親子関係」のツリーと「優先順位順の未完了一覧」を置く。
- 一覧は `順位`、`優先度`、`GitHub Issue`、`状態`、`関係・着手条件` の5列を持つ表で示す。GitHubの `state=open` で取得した全Issueを対象とし、Pull Requestは除外する。Issue番号にはGitHubへのリンクを付け、状態は「未完了」など日本語で記載する。
- 対象Issueが1件だけの場合も表を省略せず、オープンIssueを手作業で抜粋したり、件数だけを記載したりしない。
- 親子関係はGitHubのsub-issues APIから取得し、優先度と補足関係は `scripts/dev/github_issue_status_policy.json` から取得する。表の生成とHTML再生成は `python -m scripts.dev.sync_github_issue_status --repo owner/name --write` で行い、`--check` がGitHub API上のオープンIssue番号集合との一致を検証する。
- 「GitHub Issueの状態（省略）」の注記や、箇条書きだけで状態を示す形式は、新規作成・更新する作業記録では使用しない。

### 親子関係

- 親子関係は、優先順位一覧より先に専用のツリーで示す。
- 「親Issue」「子Issue」を文字で明記する。
- 親Issueの下へ子Issueをインデントし、縦線と横線で接続する。
- 親Issueと子Issueの状態、優先度、着手条件を同じ行または直下へ記載する。
- 完了した親の下に未完了の子がある場合は、それぞれの状態を省略しない。

### 関連Issue

- 関連Issueは子Issueのようにツリーへ混在させない。
- 親子ツリーの後に「関連Issue」として別枠または別行で示し、何の結果を利用するのかを書く。

### 優先順位一覧

- 親子ツリーの後に、P0からP3の順で一覧表示する。
- 各Issueには番号、タイトル、優先度、状態、着手条件を普通のテキストで記載する。
- 新しく追加したIssueは「新規 2026-08-13」のように日本語と日付で示す。
- `parent`、`child of #24`、`related #25`などの英語チップは使わない。

## HTMLの構成

作業記録HTMLは原則として次の順序にする。

1. 作業記録番号、対象GitHub Issue、結論
2. 対象と入力
3. 判断事項
4. 成果物と実行順
5. 欠損・保留事項
6. 適用結果
7. GitHub Issue状況（必要な場合のみ、作業記録の末尾）

GitHub Issue状況だけを別HTMLにしない。

## 推奨事項

- 見出しは本文より一段大きい程度にとどめ、事実をそのまま書く。
- 本文は日本語16pxを基準にし、十分な行間を取る。
- 数値は単位と項目名を併記し、必要以上に大きくしない。
- コード、ファイル名、SQL名は等幅フォントを使う。
- 親子関係は文字だけに頼らず、接続線とインデントでも示す。
- PCとスマートフォンの両方を実ブラウザで確認する。

## 禁止事項

- 英語キャッチコピーや英語だけの見出しを主要表示に使わない。
- 日本語でもキャッチコピー調、広告調、劇的な結論にしない。
- 広告ページのような大きなヒーロー、巨大な数値、抽象的なグラデーションを使わない。
- 同じ件数や結果を複数箇所で強調しない。
- 状態や分類を大量のチップ・バッジで表現しない。
- セクション名称を13px以下の小さなラベルだけで示さない。
- 親Issue、子Issue、関連Issueを同じ階層で並べない。
- 強い影、ガラス表現、グラデーション背景を使わない。
- 角の鋭いカードを大量に並べない。
